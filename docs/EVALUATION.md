# 医疗决策评测方法

v0.8.0 含 73 个有题任务、5,907 题；53 个任务各 100 题，20 个为不足量的探索性任务。开放核心集 4,334 题，非商业研究附加集 1,573 题；另 16 个任务为空。当前没有本版本的模型成绩。

## 输入与输出

模型只接收每题的 `request`，需要时按服务接口添加模型名。`state` 是材料，`questions.decision.criteria` 是候选选项。不得把 `gold`、来源标注或适配元数据作为模型输入。

预测 JSONL 每行包含 `id` 和 `choice`，或 `id` 与 `response.answers.decision.choice`。题号必须与数据集完全一致。缺失回答、无效选项、格式错误回答都按错计；重复或未知题号使计分失败。两种预测结构不得用于重复提交同一题。

## 指标与汇总

- 逐任务：准确率、宏 F1、逐类召回、来源组全对率。
- 场景汇总：同场景内各任务准确率等权平均。
- 主汇总 `scenario_macro_accuracy`：有题场景等权平均。
- 空场景：分数为 `null`，不按零分处理，同时展示覆盖率。
- 分层：语种、来源性质、决策阶段、决策模式、原始划分、样本数量完整性和历史材料匹配状态。

宏 F1 按实际有金标的类别计算，未出现的候选类别单列。能力标签允许重叠，只用于分层，不累加为主分母。默认评分范围为开放核心集；需要完整范围时显式开启研究附加集。不同覆盖范围的分数不能直接比较。

## 耗时测量与结果记录

结果按“模型版本 × 任务 ID × 固定子集”关联，同一任务的不同模型使用相同题目 ID 集合。训练前后的模型记录不同检查点，不覆盖原结果。数据版本、manifest 哈希、子集 ID 清单或其哈希、模型版本和运行配置共同标识一次评测。

### 计时边界

单题使用运行端的单调时钟计时：从开始执行该题决策流程、发出首次请求之前开始，到最终选择返回或该题明确失败结束。JEV 与其他系统都按完整决策计时，包含流程内的处理、多阶段调用、工具调用、重试及退避等待。首次 token 的时间不能替代完整决策耗时。

数据下载、一次性模型加载、预热、离线评分不计入单题推理耗时，应单独记录其设置或时间。预热题不使用评测题；缓存开启情况、是否命中和冷启动条件需记录，避免一个系统重复使用缓存而另一个系统每次重新推理。

任务总耗时使用从该任务第一题开始执行到最后一题结束的墙钟时间，包含调度间隙与运行失败。并发运行时，单题耗时之和不等于任务总耗时。各模型固定相同并发数、超时、重试上限、输入内容和输出要求；硬件或 API 服务无法保持相同时，按实际环境分别报告，不把耗时差异完全归因于模型或方法。

### 逐题运行记录

运行端另存逐题日志，通过 `run_id` 和题目 `id` 与预测关联。现有 `score` 工具只处理质量评分，不读取或汇总以下耗时字段；日志采集与汇总属于运行端工作。

| 字段 | 含义 |
| --- | --- |
| `run_id` | 本次运行的唯一标识，关联完整配置 |
| `id`、`task` | 数据集题目 ID 与任务 ID |
| `model_version` | 模型及检查点；JEV 运行也应记录底层模型与流程版本 |
| `status` | `success`、`timeout`、`request_error` 或 `invalid_answer`；重试后仍失败时记录最终状态 |
| `elapsed_s` | 含全部尝试、处理与等待的实际单题耗时，非负秒数 |
| `attempts` | 该题执行尝试次数，包含首次尝试 |
| `model_calls` | 该题实际模型调用总次数，多阶段调用与重试都计入 |

运行配置另记数据版本与子集、提示模板、生成参数、输出/token 限制、硬件或服务端点标识、推理精度、并发数、超时、重试策略及缓存状态。配置和日志不保存 API 密钥。任务墙钟起止点单独记录，不能用单题耗时求和代替。

### 逐任务汇总

每个模型在每个任务输出一行结果，至少包含：题数、尝试题数、有效完成题数、准确率、宏 F1、平均单题耗时、P50/P95、任务总耗时、超时率、请求失败率、无效回答率和重试总次数。

平均耗时与 P50/P95 默认统计所有实际启动题目的结束耗时，包括最终失败题；未启动题不填 0，也不进入耗时分布，但仍在质量评分分母中按缺失回答处理。可另外报告成功题耗时，必须标清分母。失败耗时是截至失败/超时的观测时长，不代表完成决策所需时间，因此耗时应与完成率和得分共同阅读。超时率、请求失败率和无效回答率以实际启动题数为分母，未启动数量另列；重试总次数为各题 `attempts - 1` 之和。

P50/P95 采用升序观测值的 nearest-rank 定义，第 `ceil(p × n)` 个值（从 1 开始计数），没有观测时记为 `null`。少量题目的 P95 可能就是最大值，应同时展示样本数。预热和重试设置固定后再比较；如做多轮重复运行，逐轮保存结果，并报告运行间变动。

当前没有已发布的模型得分或耗时榜单。空任务记为待补数据，未运行的模型记为未评测，两者都不填写假设成绩或零耗时。

## 抽样与来源组

从固定版本解析原标注，以声明的标签、量表或来源等分层抽样，固定种子为 20261010。先尽量每来源组一题，再按规则放宽到每组最多五题。去除重复请求、冲突答案、不能可靠解析的标注和冻结本地训练指纹命中。数量不足时保留实际数量，不改写或复制补题。

`group_id` 表示来源文档、句子、模拟病例或患者组，不保证一律是患者。LongHealth 两个任务各 100 题，共用 20 个虚构患者；各任务之间也可能共享材料。比较模型或训练前后差异时应使用相同题目、选项、提示与评分范围，并按来源组配对或聚类分析，不能把共享文档内的题目都当成独立患者。

UCI 结局预测按其声明的自然分布抽样；新增脓毒症任务按标签分层抽样，改变了类别比例。分诊、考试和材料任务按各自规则抽样。小样本任务不宜与完整任务的精度等同看待，另看 `sample_completeness` 分层。详细协议见 [v0.4.0 扩展](EXPANSION_V040.md)。关系选择中的实体 ID 不是跨病例医学类别，其宏 F1 不作临床类别指标解释。

## 暴露与适用范围

已保留冻结筛查索引和逐题暴露标记。当前题目没有命中该索引内的训练指纹；677 题材料或片段命中过往评测指纹，通用片段可能造成误报。该检查不能证明不存在翻译、改写、患者级关联或基础模型预训练暴露。

其中 406 题原属上游公开训练划分（中文 CMB 306 题、PhysioNet 100 题），已标记并提供 `upstream_split` 分层；若模型训练使用过这些数据，应单独剔除或报告，不能称为盲测。

用于评测训练效果时，应将本集隔离于训练数据；不要根据测试分数挑换题目。每任务 100 题适合初步固定对照，尚不足以确认细小改进或临床有效性。当前评分是描述性统计，没有自动计算显著性或置信区间。

来源含公开病例报告、临床材料、考试改编和模拟病例，各自性质逐题记录。答案来自上游标注与机械映射，尚无本项目独立医生逐题审核；场景覆盖也不表示完整临床工作流能力。

## v0.5.0 新任务的解释范围

脓毒症固定时点预测采用公开训练来源自留子集，11 个阳性、89 个阴性。至少同时报告两类召回；恒答阴性的准确率为 89%，不作为临床性能证据。该目标不同于原挑战逐小时 utility，不能与其排行榜直接比较。隐私任务是给定词判断，不能报告为全文脱敏召回；参考区间任务是给定资料条件匹配，不能报告为独立诊疗知识正确率。详见 [适配协议与限制](GAP_AUDIT_V050.md)。

## v0.6.0 新任务的解释范围

CPIC 是固定指南规则评测，功能表型 84 题仅覆盖 19 个基因；用药建议 100 题覆盖 25 个指南。应报告来源组，且不能将候选 ID 的宏 F1 解释为统一医学类别指标。LabQAR 判读使用给定区间和作者构造数值。Evidence Inference 判断比较试验报告的效果方向，不直接选择最佳治疗；其 100 题来自 100 篇文章。前版所有 5,210 条完整记录保留，可按 ID 使用相同子集比较。详见 [适配协议](EXPANSION_V060.md)。

## v0.7.0 新任务的解释范围

病机候选核验的 100 个判断仅含 50 个病例，每病例一个正候选和一个负候选。应以病例为单位分组或重采样，不能按 100 个独立病例解释区间，也不能与原始多选整集合准确率直接比较。处方审核处置、营养方案与体位选择分别只有 11、11、10 题，须单列数量和标签分布，不能据此判断细小训练增益。上游训练划分仍需按模型训练暴露情况剔除或分层。

## v0.8.0 分层

PMR-Synth 仅在非商业附加集内计分，单独报告其训练/测试映射未知的 30 个比较。记录信息充分性来自 20 个已用的虚构患者，yes/no 各 50；按目标患者分组，其异患者干扰文档也跨题共享，因此不能把简单逐题置信区间当作独立患者层面的区间。八类新增情境选择任务只有 3–13 题，分数波动很大，适合发现错误类型；等权汇总可能放大小样本影响，应同时报告逐任务样本数与旧版任务子集分数。
