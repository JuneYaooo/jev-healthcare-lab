# 评测设计与证据边界

## 当前回答了什么

本项目评测 Jev 作为医疗软件中的结构化判断组件，使用归档模型 `jev-1.13.0`。目前已有 96 个任务条件、7,133 条输入，以及独立保留的扰动、批量与上下游误差实验。原始请求、金标、响应、费用和文件哈希均可离线核验。

这些证据足以筛选值得进一步验证的任务，尚不足以证明临床部署安全或改善患者结局。公开开发集、小样本、给定标准实体、候选集筛选和自编挑战占有较大比重；任务数量不能代表完整医疗工作流覆盖率。

**当前最合理的定位：医疗结构化组件的探索性评测与后续实验框架。** 分类、抽取和证据筛选可作为人工辅助方向；诊断、治疗、临床计算、入组判定仍需要独立验证与人工复核。具体数字见[适用性审计](医疗适用性审计.md)。

## 参考什么，如何采用

| 来源 | 采用的方法 | 本项目的适用范围 |
| --- | --- | --- |
| [MedHELM，Stanford，2025 原始论文](https://arxiv.org/html/2505.23802v1) | 用真实医疗任务组织评测，按任务选择指标，结合成本分析 | 按业务任务报告，不把考试正确率当成整体医疗能力，也不合并不同口径成总分 |
| [HealthBench，OpenAI，2025](https://openai.com/index/healthbench/) 与 [官方评分实现](https://github.com/openai/simple-evals/blob/main/healthbench_eval.py) | 场景特定的医生评分标准，关注有益行为、遗漏和有害行为 | 借鉴具体错误方向与专家复核；当前未运行 HealthBench，不宣称获得其分数 |
| [MedBench 官方平台](https://medbench.opencompass.org.cn/home) | 中文医学知识、语言理解与生成、复杂推理、安全伦理的多维评测 | 中文任务需覆盖实际语境与风险；本仓库的公开数据适配不等于官方 MedBench 榜单结果 |
| [TRIPOD-LLM，Nature Medicine，2025](https://www.nature.com/articles/s41591-024-03425-5) | 明确数据、模型、提示、评估、人类监督及局限性 | 保存身份、版本与失败，区分探索性再分析和未来独立实验；不声称通过指南认证 |
| [Jev 官方介绍](https://docs.typesafe.ai/introduction) 与 [confidence 文档](https://docs.typesafe.ai/confidence) | Choice、Score、Noul 结构化判断；概率分布与 confidence 分开解释 | 本归档主要测 Choice/Noul；confidence 是分布的摘要，不能当成独立证据或临床风险概率 |

以上链接于 2026-09-30 核对。HealthBench 主要评估开放式对话回答，而 Jev 官方接口主要输出类型化判断。将对话改成选择题会改变评测任务；如果将 Jev 用作评分器，还必须另测其与医生判断的一致性，不能用它评自己的输出证明质量。

## 业务覆盖审查

| 工作 | 已有证据 | 尚缺的关键验证 |
| --- | --- | --- |
| 病历整理与编码辅助 | 给定实体分类、词典／medspaCy 候选抽取、章节分类 | 完整文书的事实保留、遗漏、错误添加；真实接入的候选召回与人工耗时 |
| 患者咨询和分流 | 意图分类、给定政策的紧急程度、科室候选 | 前瞻分诊敏感度、紧急事件漏判、信息不足时升级、不同人群与机构验证 |
| 用药与质控 | 药物对关系、出院带药候选、文本错误检出 | 当前用药核对、剂量／单位错误严重度、医生逐例判定与纠错收益 |
| 入组预筛 | 试验匹配分类、证据定位 | 每条纳排条件与引用依据、未知条件处理、患者级召回和医生节省时间 |
| 循证研究 | 给定文章／摘要判断、证据句筛选 | 检索完整性、文献时效、引用真实性、全文到结论的链路质量 |
| 临床计算 | 参数选择、闭集分数、少量 BMI 程序组合 | 真实单位换算、缺失／矛盾处理、程序计算与完整病例配对验证 |
| 语音／扫描工作流 | 公开演绎音频和扫描件的文本下游任务 | 真实噪声、人群与设备变化；不能据此认定 Jev 原生读图或听音频 |
| 对话、病历生成、临床代理 | 当前没有对应端到端实测 | 对完整组合系统另行设计；医生评分、工具操作正确性和实际效果 |

## 统计口径

1. **独立单位。** 用 `case_key()` 合并同一来源病例／文档的多条判断，保留 OCR 扫描变体与音频字段的关联。病例不一定等于患者；不同任务可能复用相同病例，不汇总成患者总数。自编模板相关性和机构相关性可能仍未充分建模。
2. **配对比较。** 每次 bootstrap 抽同一批来源案例给两模型，计算 Accuracy 或汇总 TP/FP/FN 后的 micro-F1，再求差值。2,000 次重采样固定种子；95% 区间是逐任务、探索性的，未做多重比较校正，不能从 96 项中择优宣布显著优势。
3. **业务完整度。** 同时报告病例全部正确率；任一字段错误、集合不完全匹配或接口失败即该病例不全对。既有集合 F1 中失败按空集计，其局限通过单列失败及病例全对呈现。所有计划输入保留在分母中。
4. **错误方向。** 不用总正确率掩盖有害请求放行、医疗错误漏检、资料不足却通过、未知症状被当成阳性。标签定义不代表已完成临床严重度仲裁。MedSafetyBench 与正常请求来自不同来源，其筛查效果可能受到来源差异影响。
5. **概率。** Choice 的所选标签概率和 API confidence 分别计算筛选结果；记录 Brier、ECE、接受比例、剩余错误及复核量。DeepSeek 的硬标签不伪装成概率，不与 Jev 比校准。固定阈值的历史表现不能直接成为上线策略。
6. **零错误。** 已接受病例的“至少一条错误”给出 Wilson 区间，零错误也有正的风险上界。它假设案例独立，不是逐字段或部署风险的保证。bootstrap 在全对样本上可能退化为零宽度，不应解读为完美可靠。
7. **基线与成本。** 保留原规则／词典基线；测试集多数类比例仅是描述性参照。费用是历史 token 与价目估算，不代表当前报价或账单。缓存、失败重试、OCR/ASR、人工复核和基础设施需要在真实业务中共同计费；历史两模型延迟不能作同期速度比较。

## 下一轮实验协议

### 数据与封存

- 先明确单个工作流、目标人群、机构、语言、使用者及错误后果，再指定主要指标、风险上限、比较对象和人工复核策略。
- 以来源病例／文档为单位抽样，开发集用于提示与阈值选择；冻结后仅评估一次测试集。患者、模板、机构或时间隔离按目标另外设置。样本量需按预期差异、相关性与风险上界设计，不能用固定 20 或 100 条作为充分依据。
- 新数据保存来源版本、授权状态、去标识化状态、采样种子、金标来源及专家分歧。两个独立临床评审盲评高风险错误，分歧交第三位评审仲裁；记录一致性。当前公开历史标签与医生复核完成状态应分别报告。
- 使用 `freeze_evaluation.py` 固定配置、来源文件哈希、样本身份、开发／测试分组。它合并相同案例及完全相同的 state，避免跨任务重复文本进入不同分组。它不识别语义近重复，也不能证明未见过数据；必要时先做额外去重。

```sh
# 演示旧数据的固定划分：仍属于回顾性实验
python3 scripts/freeze_evaluation.py create \
  --input scenarios/quality/medsafety_request_gate/samples.jsonl \
  --config evaluation/protocol.example.json \
  --output work/frozen-demo
python3 scripts/freeze_evaluation.py verify work/frozen-demo
```

输出 `development.jsonl`、`test.jsonl` 供本地计分，`*_requests.jsonl` 只含请求及身份，供推理使用。既有 `live_batch.py --input` 可读请求文件，其发送体只有 `request` 和模型；原金标不进入请求。输出目录必须是新目录。文件哈希用于一致性检查，不是可信时间戳或防篡改签名。

示例配置只用于探索性试验，不是已批准的临床准入协议。运行器不会自动执行配置中的调用预算、重试策略或临床验收条件；执行时须显式设置运行参数，并核对实际记录。模型别名可能更新，要同时记录响应返回的模型标识。历史数据重新分组不能变成真正的前瞻测试。

### 比较与验收

至少比较现有规则／词典方案、Jev、同输入通用模型和需要时的人工辅助方案。候选、证据、字段、超时及重试条件保持一致；通过可随机交替的运行顺序控制缓存和时段影响。仅传输或格式失败可按预设重试，答错不重试。

阈值与拒答规则只在开发集决定，测试集报告原始分母、覆盖率、升级量、错误方向、病例全对率、区间、延迟 p50/p95 与实际费用。若风险上界、关键亚组样本量或人工流程验证不满足预定条件，结论为证据不足。离线通过后仍需真实工作流的静默验证；本项目目前没有这部分证据。
