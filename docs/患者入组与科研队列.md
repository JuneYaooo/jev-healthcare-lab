# 患者入组预筛与科研队列

值得优先研究的是入组预筛、逐条件证据核对和缺项待办。病历结构化可作为上游，但未记录某病史不能解释为不存在，符合预筛条件不等于完成入组。

## 业务范围

| 场景 | 可交给Jev的语义判断 | 应验证的收益 |
|---|---|---|
| 临床试验招募 | 已检索患者与逐条纳排条件是否匹配 | 合适患者漏检、每例复核时间 |
| 回顾性研究 | 诊断、治疗史、事件时间符合研究定义 | 队列准确率和人工筛查时间 |
| 病种登记库 | 是否符合登记定义、字段是否缺失 | 登记完整率与纠错工时 |
| 慢病管理 | 按项目既定标准分流到管理路径 | 错分流与接管率 |
| 出院随访 | 适用路径与缺失信息提示 | 遗漏和重复核查 |
| 入组后核查 | 新检查或治疗变化影响了哪些条件 | 有效提醒与误报负担 |

这些是应用设计，不是全部已测试场景。

## 推荐链路

病历原句和时间 → 结构化候选 → 代码处理数值阈值/时间窗 → Jev处理歧义语义 → 每条条件输出满足、不满足、信息不足或证据冲突 → 研究人员确认。

Jev应选择已有证据ID，程序回填原句，避免生成看似合理但不存在的证据。复杂AND/OR、排除条件的方向、治疗线数、洗脱期和方案版本需要明确建模。未知项形成补检查或核实病史的待办，不直接作为排除理由。

## 本轮已有测试，不夸大为入组成功率

TrialGPT SIGIR适配三分类150条，准确率48%。每类50条，真实与预测如下：

| 原标签 / 预测 | irrelevant | potential | eligible |
|---|---:|---:|---:|
| irrelevant | 44 | 6 | 0 |
| potential | 25 | 23 | 2 |
| eligible | 12 | 33 | 5 |

若自动丢弃irrelevant预测，会遗漏该样本50条eligible中的12条。这个协议不能用于自动淘汰患者。逐条件四状态流程尚未独立验证，不能声称一定解决上述错误。

NLI4CT给定试验文本推断88%，证据选择F1约49.9%；不是患者入组准确率。项目入口：[TrialGPT](https://github.com/ncbi-nlp/TrialGPT)、[NLI4CT](https://github.com/ai-systems/nli4ct)。原TrialGPT由检索、逐标准匹配和排序组成，本轮没有复现其完整框架。

首个试点应固定单病种、少量项目、方案版本与独立人工金标，测合适患者召回、每病例复核分钟数、缺项提示正确率和错误排除率。没有医院真实数据与工时之前，不报已实现的ROI。
