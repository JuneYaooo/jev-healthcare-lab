# v0.8.0：场景决策与缺失证据

本版补充八类决策任务，并为消息优先级、记录信息充分性两个原空缺提供数据。v0.7.0 的 5,726 条完整记录保持不变。新增 181 题，总计 5,907 题，73 个有题任务、16 个空缺；不足 100 题的任务仅提供探索性覆盖。

## 场景与边界

| 场景 | 新增或补齐任务 | 主要来源 |
| --- | --- | --- |
| 接诊与分诊 | 两条消息的处理优先级、记录信息充分性 | PMR-Synth、LongHealth |
| 治疗与用药 | 给药途径与实施方法 | CMB、CNMLEQA |
| 住院与护理 | 监测指标、感染防控措施 | CMB、CNMLEQA |
| 出院与随访 | 随访方案、康复训练、个体预防、患者教育与沟通 | CMB、CNMLEQA、MedMCQA |
| 病历与医疗质量控制 | 知情与隐私处置 | CMB、PrinciplismQA |

随访方案评价复查项目或时机，不代表完成/逾期待办判断。监测指标评价持续观察什么，不重复诊断题。给药方法评价如何实施，不重复原文药物途径关联。预防题以暴露或复发前的行动为目标。所有题只输出一个原选项或固定标签；不要求生成病历、建议、解释或沟通话术。

## 原题选择

CMB 与 CNMLEQA 扩展关键词筛查产生 216 个去重候选，固定保留 47 道；排除意图误匹配、上下文不全、缺选项、近重复、相似题答案冲突和明显需要进一步核验的题。`selection_v080.json` 记录固定资源位置与问题哈希。范围筛查不是独立临床专家审核；不修改上游题目或答案，不将原题答案认证为现行诊疗建议。CMB 测试答案仍按 ID 连接独立答案文件，上游训练题逐条标记。

[MedMCQA](https://huggingface.co/datasets/openlifescienceai/medmcqa) 使用官方 validation，只保留 `choice_type=single` 的两道新任务病例题。沿用 `cop` 的 0–3 到 `opa`–`opd` 映射。数据许可依据发布数据卡 Apache-2.0，独立于代码仓库许可。[论文](https://proceedings.mlr.press/v174/pal22a.html)描述考试题来源；这些材料不是患者队列。

[PrinciplismQA](https://github.com/FreedomIntelligence/PrinciplismQA) 的明确 MIT 发布声明和许可随包保存。2,182 道 MCQA 经范围筛查，仅取两个患者意愿/隐私处置题；不收伦理原则名称辨认及开放式问题。[论文](https://aclanthology.org/2026.findings-acl.1806/)说明题目由模型基于教材构造、经医学专家审核，来源卡据此标为合成题。原解释和伦理分类不进入模型输入。少量伦理题不能代表所有地区的法律或伦理共识。

## 消息优先级

[PMR-Synth 原始发布](https://huggingface.co/datasets/PortalPal-AI/PMP-Synth-AllPairs-Annotated)包含两个收件箱、869 个有标注对比，共 60 条不同消息及病历背景。[论文](https://arxiv.org/abs/2601.13178)将这些人工合成消息的直接人工比较标注，与 Reddit 子集的推导标签区分。本版只使用前者。答案直接沿用 `Label`，保持消息左右顺序。

固定种子按对比哈希排序后，贪心保留没有使用过的消息与病历，得到 30 个比较。每条消息和病历仅出现一次；这仍是两个收件箱的材料，不能推断为 30 个独立临床就诊。不得从排列组合中凑出 100 个“独立样本”。

INBOX_A/B 与论文训练/测试收件箱的对应尚未确认，逐题标为 `published_inboxes_train_test_mapping_unresolved`。本子集适合已知材料上的对照，不是已证实未暴露的官方盲测集。原数据采用 CC-BY-NC-4.0，只进入非商业研究附加包。

## 记录信息充分性

[LongHealth](https://github.com/kbressem/LongHealth)同版本 `task2.py` 定义了目标患者证据文档有/无时的答案。依据原 `answer_location` 定位整份证据文档，机械投影为 yes/no；不由模型重新判断答案，不生成临床金标。

每个虚构患者固定选五个不同问题，交替构造证据存在或缺失，合计 100 题，yes/no 各 50。每题附两个固定的其他患者干扰文档；阳性额外含全部原证据文档，阴性完全没有目标患者文档。不截断内容，输入不含原答案、证据位置或有无标记。文档展示顺序与问题选择由固定哈希确定。

该子集评价记录证据可用性，不覆盖计算缺项或冲突消解。它与原文档检索任务共用 20 个虚构患者，干扰文档也跨题复用；应按来源患者分组，不能称 100 个独立患者。固定两个干扰文档及二分类输出与原始十次随机、token 限制、六选项协议不同，不能将本任务分数直接称作原 LongHealth Task 2/3 成绩。

## 可复现性与检索边界

原 Parquet 和无损 JSON 解码同时冻结。`sources.lock.json` 锁定原始文件 URL、版本和哈希；`table_exports.json` 单独锁定解码文件，不把转换后的 JSON 冒充原始下载。逐题记录原 Parquet 的零基行号。普通重建和离线使用只需 Python 标准库；独立重解码核验可用 PyArrow，见复建说明。

本轮继续检查了治疗结局、分诊、药物状态、伦理、随访行动和缺失证据等来源。结论记录在 [扩展核验表](../benchmarks/medical_decision_v1/expansion_audit_v080.json)，其中保留 16 个空缺及各自原因。UCI 冷冻治疗表的内嵌使用协议与外层许可存在冲突；MIMIC 派生的 MedDec、CICTD、CLIP 等不能直接开放打包基础记录；其他候选存在底层许可未确认、仅开放式评分、缺少可取的原金标，或任务与现有覆盖重复的问题。

停止边界是本轮已检查来源中没有剩余可直接纳入的新任务，不是宣称医学数据集已穷尽。新增来源、许可澄清、原金标公开或正式临床审核可以改变结论。历史 `gap_audit.json` 保留 v0.5.0 当时状态，不覆盖后续已补齐任务。
