# Jev医疗深度调研与实测报告

2026-09-24。结论：**值得优先做病历候选字段的复核、章节/消息分类、证据支持判断与人工复核队列；当前结果不支持把Jev直接作为完整病历生成器、自动处方器或独立分诊系统。** 医疗与自媒体已分开报告。不能承诺穷尽所有可能场景，也不能把90个资源入口等同于90个已完成基准。

本轮将上一版2,108条医疗评测扩展到**6,586条医疗记录**，涉及72个公开数据或公开材料适配的任务条件，另含24类自编挑战96条；这些条件含同一病例不同问题和证据消融，不是独立患者数。另完成300条配对鲁棒性扰动、自媒体1,669条，合计**8,555条可计分记录**。其中43条无实体候选，由程序给出空预测，不调用API。除此之外均有真实响应，接口示例另计，不用模拟结果充数。

模型固定jev-1.13.0；用户提供的jev-latest在检查时解析到此版本。没有用其他模型替Jev回答。每项任务保留请求哈希、金标来源、响应、token与延迟。完整逐任务表见《结果总表.md》，详细逐类指标、区间与校准见all_results.json；原始研究目录与未完成项见《覆盖与阻塞账本.md》。

## 病历结构化能做什么，实测到了哪一步

最可行的链路是：文本/OCR/ASR → 候选实体、数值、原句位置 → Jev判断类型/状态/关系 → 术语与规则校验 → 带证据的人工复核 → 写入业务系统。候选召回失败，Jev无法从不存在的选项中找回字段；结构化中的“未知”必须区别于“否定”。

| 环节 | 本轮结果 | 实际意义 |
|---|---|---|
| 中文给定实体的类型识别 | IMCS 100条，96% | 边界已知的分类，不能称96%的端到端抽取 |
| 中文病历实体管线 | IMCS词典候选＋Jev严格F1 59.5%，词典42.6% | 有提升，但精确率约52%，仍有大量误报 |
| 英文实体管线 | NCBI 100篇，medspaCy F1 58.9% → 加Jev 69.4% | TP596→592，FP467→155，FN364→368；主要减少误报，仍遗漏368个实体 |
| 否定/不确定性 | IMCS 79%；BioScope句子线索83%；NUBes否定/不确定二分72% | 三项定义不同；NUBes没有肯定对照，BioScope不是实体作用域准确率 |
| 同义词标准化 | IMCS候选归一93%，简单别名基线98% | 规则能完成的标准映射不宜无条件交给Jev |
| 病历章节归类 | MTS 76%；ACI已给定章节边界时99% | 可以辅助归档，不能据此宣称会生成完整SOAP病历 |
| 药物关系 | DDI给定实体对79.3%；BC5CDR给定实体的化学致病关系57% | 问题定义影响很大，不足以自动审方 |
| 出院用药集合 | CDrugRed候选管线F1 48.6%，简单top5基线25.4% | 候选召回仅67.4%；取自按患者分离的发布训练池，不是官方隐藏测试成绩 |
| BMI参数＋程序公式 | 20病例，正确输入对17/20；首个数值基线14/20 | 两参数的单项选择各95%会掩盖候选缺失；真正完成率85% |

英文medspaCy基线100篇约1.55秒，Jev增加网络请求和费用。本轮尚未测出减少312个误报可节省多少人的复核时间；也未证明漏掉的4个正确候选的代价低于收益。端到端F1不是医院工时节约率。

## 高频医疗流程如何降本增效

“高频”是流程判断，尚无某医院实际日均量统计。先选大量重复、可回滚、输出有限且容易人工核对的环节。

| 优先级 | 高频场景 | 具体产品与Jev职责 | 验收指标 |
|---|---|---|---|
| P0 | 病历整理、科研入库、随访归档 | 给候选症状/药物打类型、肯否定、当前/历史、本人/家属标签；点标签可回到原句 | 字段级P/R、证据定位正确率、每份病历复核秒数 |
| P0 | 患者消息、报告咨询与运营收件箱 | 意图分类、转人工、缺少材料提示；紧急词先走既有规则 | 错转率、人工接管率、漏掉紧急消息的数量 |
| P0 | 文书质控 | 查缺项、前后矛盾、来源不支持的字段，生成复核队列 | 每百份有效问题数、误报工时、修订率 |
| P1 | 检验数值入库、评分表 | OCR/解析器召回值，Jev判断归属和时间，单位换算与公式由代码执行 | 项目-值-单位-时间整组正确率，不能只测数字出现率 |
| P1 | 临床研究/系统综述 | PICO和证据句筛选、研究结论支持/反驳、纳排标准初筛 | 高风险漏排、候选召回、文献复核工时 |
| P1 | 术语编码 | 标准库检索候选，Jev处理规则无法决定的歧义 | 候选Recall@K、编码准确率、unknown处理率 |
| P2 | 药物核对和出院计划 | 标记候选遗漏/矛盾，交药师或医生确认 | 严重错误漏检率、每次有效警报成本 |
| 暂不自动执行 | 急诊风险等级、诊断、处方、医保拒付等后果较大决定 | 仅影子评估和复核提示；不能由考试成绩替代场景验证 | 专科金标、自然患病率、前瞻性复核与错误成本 |

仍有重要场景没有可直接使用的公开金标：多次就诊纵向合并、复杂时间线、药物启停/剂量变更、护理事件、手术并发症、肿瘤分期、真实医保/DRG质控、去标识化的残余泄露率、医院短信/语音分流。已有96条自编挑战覆盖其中一些规则边界，但这只是管线冒烟，不能称临床验证。更完整的业务地图见《医疗工作流全景.md》。

## 循证、错误检查、考试和安全必须分开看

| 用途 | 本轮实际结果 | 限制 |
|---|---|---|
| 医学回答幻觉检查 | MedHallu同一100问题×真/幻觉回答：无证据60%，有证据82% | 有证据时幻觉召回89%，正确答案也有25%被误判；不能盲目拦截 |
| 文献是否支持结论 | SciFact 85.6%；NLI4CT entailment88%；Evidence Inference89% | 都提供了相关文档；没有测试检索全流程 |
| 找具体证据句 | NLI4CT F1 49.9%；EvidenceBench F1 29.4% | “结论判断正确”不等于“证据位置正确” |
| PICO/结局抽取适配 | EBM固定窗F1 12.7%；EvidenceOutcomes二分类88% | 任务、抽样与阳性率不同，不能直接比较或称官方NER成绩 |
| 病历错误检出 | MEDEC65%，错误召回43.1%；MedErr中73%、英81%、阿69.1% | MEDEC漏错较多；不同语言是不同题，不能相减当语言影响 |
| 试验推荐 | TrialGPT SIGIR三类150条48% | potential与eligible边界困难；不是完整TrialGPT逐条推理/检索评测 |
| 医学知识选择题 | MedQA英83%、中89%，MedMCQA72%，CMExam单选92.6% | 不同试卷、不同选项数；不是诊断/处方或医院效率指标 |
| 闭集临床量表选择 | MedCalc-Verified 100条25%；5个评分各20条 | 当前提示未提供公式，允许unknown；不是全部55种计算器，也不是公式程序基线 |
| 合成鉴别诊断 | DDXPlus 100条67% | 第三方镜像有限前缀样本，仅正性/分类症状；非真实患者、非完整官方测试 |
| 有害请求入口 | 100有害＋100正常，准确率93.5%，有害召回87% | 标签取决于数据来源，存在来源混杂；不测生成回复安全性 |
| 中医 | TCM-SD 33%；TCM-BEST不同维度见全表 | BEST安全题27%是与原始标签一致率，部分标签对正常问题也要求拒答，不能当安全率 |

PUBHEALTH另做100个历史公共卫生论断配对：无文章20%，有文章67%。所给文章是事实核查报道，可能直接写出结论；这测的是利用已提供核查材料，不等于自行核实最新事实。没有把解释金标直接放进输入。

## OCR、ASR与鲁棒性：真正跑了上游，但规模很小

ClinOCR-Bench六类失真各一个文档，实际使用Tesseract；只有两种模板文本，多份失真不是独立患者。Jev文档类型判断在干净参考文本6/6，OCR文本5/6。数值token集合召回忽略字段关联，不能证明把数值写进正确检验项目。尚未完成完整表格与字段抽取评测。

PriMock57一段457.92秒的扮演患者声道，实际Whisper tiny.en量化模型转写约8.66秒，去掉参考转写编辑标签后WER32.2%；下游12个人工定义字段，参考转写12/12，ASR文本11/12。职业字段漏掉，食欲措辞也发生了明显转写变化。单段演示没有统计代表性，更不代表真实诊室、中文或双人分离效果。

鲁棒性在5个任务各20个原始案例上，分别做重复调用、选项标签轮换、添加无关说明，共300请求。重复条件100题中1题变化；标签轮换100题中8题变化，其中CMedCalc20题有6题变化、正确数16降至10；无关说明100题中3题变化。概率/置信度不是正确性证书，应在独立开发集确定阈值，再在独立测试集检验覆盖率与错误率。本轮阈值分析仅是同批样本上的探索，不能直接成为上线门槛。

## 费用低，并不自动等于降本

[官方价格](https://docs.typesafe.ai/models)为输入每百万token $0.042、输出免费。本轮医疗成功响应中位网络延迟约0.75秒、P95约1.65秒；包含客户端网络、并发和服务负载，不是芯片推理耗时，也不能转用社区的100毫秒宣传数。

全部计分成功响应合计输入9,887,701 token，按上述价格约$0.4153，只表示已留存成功响应的估算费用。接口示例、失败请求、磁盘满时可能未保存的请求费用无法完全核对；不是完整账单。输出usage虽可能非零，但价格说明为输出免费。没有支付账户或发票核查。

真正的每月收益应计算：

`处理量 × [原人工秒数 − (接纳比例×复核秒数 + 转人工比例×原人工秒数 + 返工率×返工秒数)] × 人工小时成本/3600 − API/OCR/ASR费用 − 集成维护成本`

例如纯假设：每月10万份，每份人工60秒，70%进入快速复核每份15秒，30%仍完整人工，2%返工每份120秒，则平均30.9秒/份，理论减少约808小时/月。若快速复核实际要50秒，节约降至约128小时；若再引入较高错漏成本，收益可能为负。这是敏感性示例，不是本轮测出的医院ROI，不采用臆造工资换算收益。

## 值得做的方向，以及“还没人做”的证据边界

1. **带原句证据的病历结构化复核台**：已有NER、术语库和Jev判断组合起来，把未召回字段、低可靠字段与矛盾字段显式展示。竞争点是整组字段正确率和复核工时，而不是API价格。建议先选随访/科研记录，避免直接自动写入诊疗结论。
2. **中文临床判断公开评测包**：跨科室、跨医院模板、否定/主体/时态/药物启停的最小对照、自然频率测试和错误成本。现有数据碎片化；本轮没有找到成熟的Jev中文跨医院前瞻验证，但不能证明不存在。
3. **证据支持＋缺项检查服务**：Jev只判断“这条结构化结论是否被该段原文支持”，先检索再判断。MedHallu的配对结果支持继续测试此方向，证据句定位低分说明仍需保留人工审阅。
4. **临床计算器参数门控**：用代码算公式，Jev从原文候选中判断当前患者、当前时间的正确参数；缺项就退回。BMI演示显示收益空间，也显示不能用单字段准确率替代整条完成率。
5. **临床试验初筛的未知条件队列**：不承诺自动入组，重点把“需要补哪些信息”交给研究协调员；本轮直接三分类48%不足以支持独立推荐，必须逐标准、有证据地重测。

开源社区已有PulseLane分诊演示、韩/日医学考试研究，自媒体已有广告识别和逐句评分；详见《社区项目与证据.md》。不能把这些方向声称为无人竞争。PRomop的Jev集成目前只取得作者X帖的目录线索，尚未直接核实具体实现。

## 当前仍不能声称完成的部分

90项目录中含访问受限数据、没有正确标签的数据、数据生成器、非文本任务以及替代工具。每项状态和链接在《覆盖与阻塞账本.md》。MIMIC/i2b2/n2c2等获准数据、CBLUE具体资源访问、临床人工金标、医院工时及复核成本，都尚未取得；没有代用户签署协议。目录中非原生图像/ECG、未运行的替代框架、DDXPlus全量与MedCalc其余计算器也明确留空，不能冒充全部测试。

样本大多只有100左右，公开数据可能进入闭源模型训练集；不同条件反复使用同一问题，不可合并成临床总体准确率。输入结构、抽样、提示词和候选阈值都是本轮实现选择。所有结果定位为选场景、找失败模式和设计后续验证的探索性证据。
