# 性能测试工作负载

[测试协议](../../docs/PERFORMANCE.md) · [结果](../../docs/PERFORMANCE_RESULTS.md)

- `clinical.jsonl`：从既有开放许可临床题中按任务轮转、按固定哈希顺序抽取 128 道原题。保留原输入、候选项、金标和来源。没有新生成临床答案；来源许可见每条 provenance 及[第三方声明](../../THIRD_PARTY_NOTICES.md)。
- `fanout.jsonl`：3 份原创合成文档受理看板，每份 200 条记录。固定状态，问题数依次为 1、10、50、100、200；每个问题对应不同记录。金标由明确的优先级规则计算。仅用于性能与协议完整性测试，不纳入临床主分数。
- `manifest.json`：固定种子、取样方法、源清单哈希和数据文件 SHA-256。

请求只发送 `request.state` 和 `request.questions`，不发送 gold 或 provenance。看板包含显式规则，但不包含预先计算的路由答案。金标和原始响应用于离线校验。

合成看板的全部 200 条记录在每个档位保持不变；问题数增加时输入的题目文本和输出长度同时增长。看板不是 200 份真实病历，也不是同一问题复制 200 次。三份看板分别用于三轮测试，完整 200 问各有 50 个 A/B/C/D 答案，较小前缀不强制类别平衡。
